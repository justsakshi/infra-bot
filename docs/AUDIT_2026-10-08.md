# Full feature audit, 2026-10-08

These findings come from five read-only code reviews (billing, buying, deliverability, inbox health, Slack and schedule) and a review in Andrej Karpathy's style. The main ones were spot-checked against the code and live data.

Status column: **open** until fixed. Each fix ships with a test.

## Verdict
The bot is ready to use **supervised**: it reports and prepares, and a person approves anything that kills, buys or changes inboxes. It is **not** ready to run the fleet unattended. These need fixing first:
- the open website API;
- jobs that fail silently;
- a kill rule that rests on a single small test;
- warmup ownership, which nobody has decided.

## Solid (verified)
- **Purchase plans:** both ledgers claim a plan atomically before any spend, so there is no double-buy.
- **Spend gates:** approve plus a kill-switch, and spend calls are never retried.
- **Zapmail buying:** the live price is re-checked, the wallet must cover it, and account routing is strict.
- **Domain Suggester access:** deny-by-default, covering commands, actions, views and events.
- **Payloads:** every one is validated with patterns, so no CLI flags can be injected.
- **Billing watch:**
  - an unreadable provider never produces "gone";
  - Mongo being down is reported;
  - a half-read review never writes flags.
- **Placement verdicts:**
  - the team rules are coded and tested;
  - unclassified seeds are excluded from the counts;
  - a test is marked posted only after Slack accepts the post.
- **Webhooks:** HMAC-signed and de-duplicated.
- **Secrets:** `.env` is kept out of both git and the Docker image.
